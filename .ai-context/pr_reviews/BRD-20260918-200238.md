## Ingestion Findings (submitted for review, not a review outcome)

### The source is an assessment brief, not a client BRD

`docs/Requirement for SDD.docx` is titled "SDD Developer Assessment — Employee Internal Transfer Digital Journey". It carries a real business requirement in §2–§3 wrapped in assessment scaffolding (deliverables, evaluation weights, timeline, milestones). The functional baseline was drawn only from §2–§3; the scaffolding is preserved separately in `BRD.md` §10.

### All 14 open questions now carry author-proposed resolutions

The author answered every open question on 2026-09-18. `.ai-context/BRD.md` is now at **v1.1**. The reviewer's task is **ratification, not discovery**.

| ID | Proposed resolution |
|---|---|
| OQ-01 | Five hardcoded eligibility rules: 12-month tenure, no active disciplinary action, no transfer in 12 months, performance ≥ "Meets Expectations", not serving notice |
| OQ-02 | 11-state lifecycle with rejection and withdrawal paths, plus `PARTIALLY_COMPLETED` |
| OQ-03 | Mixed — Manager and HR are humans via inbound REST; org data, payroll, IT and facilities are stubbed outbound ports |
| OQ-04 | Org-data update is a hard gate; payroll, IT and facilities then fan out in parallel |
| OQ-05 | Reference data owned locally by `employee-directory` |
| OQ-06 | Effective date ≥ today + 30 days and ≤ today + 365 days |
| OQ-07 | In-portal notification only; no email |
| OQ-08 | Withdraw until `APPROVED`; rejection terminal with mandatory reason |
| OQ-09 | One open request per employee; immutable after submission |
| OQ-10 | INT tiered defaults for latency, availability, recovery and coverage, all `[Provisional]` |
| OQ-11 | Confidential HR data — masking, encryption at rest, full audit, 7-year retention |
| OQ-12 | Immutable append-only audit trail with role-scoped reads |
| OQ-13 | Bounded retry (3 attempts, 1s/4s/16s backoff), then park for manual action. No compensation. |
| OQ-14 | Employee (own), Manager (direct reports), HR (all); anything else 403 |

> **Author ≠ reviewer.** These resolutions were authored by Vaibhaw Soni, the spec author. Nothing above is approved until recorded in this file by Soumyadeep Adhikary.

### Six derived requirements requiring ratification

The resolutions introduce behaviour beyond the 18 extracted requirements: **BRD-019** (withdraw), **BRD-020** (manager decision), **BRD-021** (HR eligibility decision), **BRD-022** (audit trail), **BRD-023** (read authorization), **BRD-024** (retry and park).

### Seven consequences requiring a ruling

**C-01** eligibility rules need employee data the directory does not hold · **C-02** `PARTIALLY_COMPLETED` added to the state model · **C-03** whether `DRAFT` is persisted · **C-04** async mechanism, possibly a message broker requiring an ADR · **C-05** encryption mechanism · **C-06** JaCoCo needed to enforce coverage floors · **C-07** governing jurisdiction unknown.

### What the document does not contain

- No non-functional requirements of any kind.
- No data-protection, retention or audit requirements, despite the journey carrying employee personal data (OQ-11).
- No failure or compensation behaviour, despite §5 weighting "Security & failure handling" at 5%.
- No rejection, withdrawal or cancellation path.
